# Reference-compatible host annotation: MTD versus MTD-Explorer

## Scope and source versions
Original MTD: FEI38750/MTD, commit d488faf929b12d810d5b46742975e535e6f48397 (2024-05-07). MTD-Explorer source snapshot: 6a469b1803dc0a64294d99117fa1ef5e0b4cc143. Historical B. glabrata run: 15 libraries, reference GCA947242115v1 (Ensembl Metazoa release 63). The source snapshot is not asserted to be the historical run commit. All ten input package manifest checks passed.

## Code evidence
- Original `HostSpecies.csv`: 199 records, no TaxID 6526. `MTD.sh` lines 47–75 requires a prebuilt custom database for a non-default host. `Customized_host.sh` lines 24–51 builds genomic resources but does not build an OrgDb or GMT or update the host catalog.
- `DEG_Anno_Plot.R` lines 149–179 selects the BioMart dataset from the catalog, with no local GTF annotation fallback in that block. Lines 1222–1238 require the configured OrgDb for enrichment; lines 1374–1396 use it for GO and ID mapping. No equivalent functional resource builder was identified in the distributed scripts.
- Original `gct_making.R` lines 17–22 uses uppercase gene names; `MTD.sh` lines 482–490 uses fixed human-symbol MSigDB C2 GMT. Original `Tools/ssGSEA2.0/src/ssGSEA2.0.R` lines 275–295 intersects identifiers and stops when no sets pass minimum overlap. Config default min_overlap=10.
- Explorer `MTD_explorer.sh` lines 8454–8669 prepares local GTF annotation cache; `Create_custom_host.sh` lines 1996–2157 invokes functional resource preparation and master GMT construction; `aux_scripts/orgdb/build_gold_orgdb_from_gtf_eggnog.R` line 415 uses AnnotationForge::makeOrgPackage. Explorer filters the master GMT against actual host GCT (driver lines 8923–8979).

## Fixed-input compatibility comparison
The common historical GCT has 20,799 unique BGLAX gene identifiers and 15 libraries. TPM and GCT expression values and identifiers agree exactly. All 26,406 featureCounts identifiers match the annotation cache. The native legacy catalog cannot supply a configured species-specific BioMart or OrgDb resource, so native GO coverage is NA, not zero. The separately measured literal overlap with the bundled C2 GMT is zero (6,366 unique set names, 21,728 unique member identifiers). This fixed-GCT diagnostic bypasses the upstream blocked annotation stage; it is not an execution of the original complete workflow and not a measure of biological accuracy. No inference about possible mappings with externally prepared orthology resources is made.

The reference GO master GMT contains 21,848 sets and 11,885 gene identifiers. Of the expression genes, 11,282 match it (54.243%). The 5–500 member filter yields 11,517 sets and 10,550 unique genes. The historical score output contains 8,191 sets and 10,537 unique genes (50.661% of input) after the effective minimum overlap of 10. All member IDs in all 15 sample-specific score annotations match the independently calculated sets. The historical analysis GMT was reproduced byte-for-byte by the Explorer filter script from the supplied source snapshot. An independent reconstruction using archived eggNOG annotations and the shared featureCounts/cache ID universe yielded exactly the master GMT membership. This is a reconstruction from saved annotations, not a rerun of eggNOG or a complete independent manual OrgDb build. The actual GTF, proteome, installed OrgDb SQLite and R runtime were not in the uploaded bundle; the manifest documents the reference identity and the counts/cache IDs serve as a proxy for the GTF gene universe here.

## Reproduce offline audit
Run `python3 verify_annotation.py --original /path/to/MTD --explorer /path/to/MTD-Explorer --run /path/to/historical_run --reference /path/to/ref_6526/functional_annotation --out /path/to/new_audit` (Python 3.9+, standard library only). Use source commits listed above. The script checks IDs, exact numeric TPM/GCT values, independent GO membership reconstruction, historical filtered GMT and all sample score-membership annotations. It writes `metrics.tsv`, `GO_set_audit.tsv`, and `input_sha256.tsv`. The original GMT and other inputs are not redistributed in this audit bundle.

## Runtime confirmation on the master server (25 November 2026)
The operator ran the unmodified original ssGSEA CLI with the shared historical `host.gct`, bundled C2 GMT, original configuration and one thread, using the existing R412 Conda environment. The supplied terminal transcript reports GCT v1.2 parsing (20,799 rows, 15 columns), minimum overlap 10, and exit status 1 with `No overlap to any gene sets found in your data set!`. This is the expected identifier-compatibility stop, not a dependency failure. The CLI installed a missing `verification` package before reaching the overlap check; the environment was not a fresh recreation of the original 2022 distribution.

The operator also loaded `org.Bglabrata.eg.db` v1.0.0 through AnnotationDbi. A query using `GID=BGLAX_026407` returned 56 GO associations with IEA evidence and BP, MF and CC ontology labels. The package exposes GID, GO and KEGG-related keytypes and columns. This is an operational example, not a validation of annotation accuracy or a claim that all GMT GO associations are represented in the installed OrgDb. The latter may be filtered by GO.db version.

Run the supplied `capture_runtime.sh` from the delivery directory before installation to copy the existing raw legacy log and exit status, verify the shared GCT and bundled GMT hashes, and repeat only the inexpensive OrgDb query with session information. The script records a new query separately from the original terminal observation. No new full pipeline, legacy ssGSEA execution or network BioMart query is required.

## Interpretation and limitations
The original host catalog lacks TaxID 6526 and the distributed workflow lacks an equivalent automatic functional resource builder. The measured zero refers only to literal identifier overlap for the fixed common GCT; native GO coverage is not available (NA). The original GCT builder normally uses gene symbols, and this diagnostic intentionally bypasses that upstream stage to hold the expression matrix and identifiers fixed. It does not establish that an adapted MTD workflow with externally supplied annotation or orthology mappings would fail. The native BioMart retry loop itself was not executed. The optional full manual annotation control and full OrgDb reconstruction were not performed. The evidence supports reference compatibility, automation and reproducibility, not improved biological annotation accuracy. No inference about the experimental biology or independent animal count is made.

The original MTD source and MSigDB collection are not redistributed here. See the source commit and input hashes above. The input archive used for the offline audit is retained by the operator; the public tables and script provide a verification record, not a self-contained replacement for the original reference resources.
